## CSV de campagne (`source_id`)

### 1. Obtenir une URL d'upload

`POST /api/v1/api/campaign/sources/presigned-upload-url`

| Champ | Type | Requis | Contraintes |
| --- | --- | ---: | --- |
| `file_name` | string | oui | Doit se terminer par `.csv` |
| `file_size` | int | oui | ≤ 10 485 760 octets (10 Mo) |
| `content_type` | string | non | Défaut `text/csv` |

```json
{ "file_name": "contacts.csv", "file_size": 12345, "content_type": "text/csv" }
```

Réponse :

```json
{
  "upload_url": "https://...",
  "file_key": "opaque-reference",
  "expires_in": 900
}
```

### 2. Uploader le fichier

Faites un `PUT` vers `upload_url` :

```bash
curl -sS -X PUT "$UPLOAD_URL" \
  -H "Content-Type: text/csv" \
  --data-binary @contacts.csv
```

<Info>
Le `PUT` ne passe **pas** par Bookivox : c'est un upload **direct** vers le
storage. Conservez le `file_key` : c'est le `source_id` à passer à la création de
campagne.
</Info>

### 3. Créer la campagne

```json
{
  "name": "Campagne demo",
  "workflow_id": "c1f0a2e4-...-9b7",
  "source_type": "csv",
  "source_id": "<le file_key renvoyé à l'étape 1>"
}
```

<Note>
`workflow_id` est un **UUID public** opaque (chaîne), pas l'entier interne.
</Note>

**Erreurs fréquentes** : `422` si `file_name` ne finit pas par `.csv` ou si
`file_size` > 10 Mo ; `500` si le storage est indisponible.

## Base de connaissance (documents)

### 1. Obtenir une URL d'upload

`POST /api/v1/api/knowledge-base/upload-url`

```json
{ "filename": "faq.pdf", "mime_type": "application/pdf" }
```

Réponse :

```json
{ "upload_url": "https://...", "document_uuid": "..." }
```

### 2. Uploader le fichier

Faites un `PUT` vers `upload_url` avec le `Content-Type` du fichier.

### 3. Lancer le processing

`POST /api/v1/api/knowledge-base/process-document`

```json
{ "document_uuid": "...", "upload_url": "https://...", "retrieval_mode": "chunked" }
```
